## Summary
We are adding a `modules/brief` server module. It makes one structured model call, bounded at 8,000 tokens, over facts that already exist: stored intent, blast radius, Smart Diff file stats, PR text, the live linked issue and the Project Context union. It drops every file reference that is not a changed file or a blast-map file, caps the output, validates the record, and stores it under the `brief` key of the existing `pr_brief.json` document. That document is written with an atomic JSONB merge, so the Prior PRs `history` key is never clobbered.

The server reaches blast, Smart Diff and Project Context only through new `Container` ports. It calls the model through a new **single-shot** provider variant, which makes no schema re-ask and no transport retry.

On the client, the Overview tab gets a PR Brief section with these parts:
- a banner, built from `VerdictBanner` extended through optional props;
- a list of missing facts, keyed by a fact/status pair set that the contract owns;
- risk pills placed under Intent;
- a Review-focus list.

Each risk and focus item jumps to Files changed through `?tab=diff&file=&line=`, by way of a small `useBriefJump` hook. Files changed can now open, mark and scroll to that target once Smart Diff has settled.

  - **`normalizeRefPath(ref: string): string`:** remove one leading `./`, then one trailing `:<int>` or `:<int>-<int>`. No case folding, no backslash rewriting.
  - **`buildPrompt(input)` → `{ messages: ChatMessage[] }`.**
    - Input: PR title, body, issue `{number, title, body} | null`, intent `{ intent, in_scope, out_of_scope } | null`, blast summary (`summary` string + changed symbols `name kind file`), caller list (`file:line name` + endpoints/crons), file stats `{ path, role, additions, deletions }[]` (no patch field exists on the input type), docs `{ path, content }[]`.
    - Every text section goes through `wrapUntrusted('<label>', …)` with labels `pr_title`, `pr_description`, `linked_issue`, `intent`, `blast_summary`, `callers`, `changed_files`.
    - Docs go through `wrapProjectDoc(path, content)`.
  - **`countInput(messages, count)`:** the sum of `count(m.content)` over every message (NFR-2).
  - **`fitToBudget(input, count, max)` → `{ input, missing: BriefMissingFact[] } | { overBudget: true }`.** Steps run in this order and stop as soon as `countInput ≤ max`:
    1. drop docs from the **end** one at a time → `project_context/dropped/<path>` each;
    2. truncate the description, keeping the longest prefix that fits (binary search on chars) → `description/truncated`;
    3. cut the issue body the same way, keeping the title → `linked_issue/cut/<n>`;
    4. drop the whole caller list → `callers/dropped`;
    5. fold file stats from the lowest churn (`additions + deletions` ascending, then path ascending) one file at a time into the exact line `` `${n} more files, +${a} −${d}` `` (`−` is U+2212) → one `file_stats/folded/<n>` with the final n.

    Intent and blast summary are never trimmed. If the input is still over budget → `overBudget`.
  - **`groundAndCap(draft: BriefDraft, allowed: Set<string>)` → `{ summary, risks, review_focus, removed: { risks: number, refs: number, focus: number } }`.**
    - **Risk refs:** a ref is kept iff `allowed.has(normalizeRefPath(ref))`. Displayed refs keep their original text minus a leading `./`. A risk with zero refs left is removed.
    - **Focus items (review #2):** the item's `file` is first passed through `normalizeRefPath` and **stored bare** (no `:line` suffix, no leading `./`). The item is removed if the normalised file is not in `allowed`, or if `!(Number.isInteger(line) && line >= 1)`. So `{ file: "src/a.ts:12", line: 12 }` is kept as `{ file: "src/a.ts", line: 12 }`, and the UI never renders `src/a.ts:12:12`.
    - **Then** caps: first 8 risks, first 8 items, in model order.
    - **`cut(s, cap)`** (review #17): when `s.length <= cap` (UTF-16 units, the same measure Zod's `.max()` uses), return `s`. ## Risks & rollback
- **Seeding a brief for PR #482 changes what `seed()` produces for every `.it` test.**
  - Effect: a test that expects "no brief" on #482 would fail, and `blast.it.test.ts:244` reads the same row.
  - Mitigation: brief `.it` tests use their own PR, and the merge keeps `history`.
  - Rollback: remove the `seedBrief` call in `seed.ts`.
- **`Container` constructor gains a 4th parameter, and the blast/smart-diff routes now go through `container.*`.** This is the deliberate refactor of steps 1–2.
  - A test that patches `repoIntel` after `buildApp()` must still be honoured, which is why the closures are lazy.
  - Check `grep -rn "as unknown as Container" server/test` before step 2 ([server/INSIGHTS.md:231](server/INSIGHTS.md:231)).
  - Rollback: revert step 2.
- **Atomic `||` merge semantics.** A top-level merge replaces the whole `brief` (or `history`) value, which is intended. An implementer who writes nested `jsonb_set` instead could leave fields from an older brief behind.
  - Rollback: revert `upsertHistory` to its previous body. The brief writer is new.
- **Single-shot provider instances.** A transport error now fails the brief immediately (`llm_error`) where other features would have retried. This is intended (SA-3) and limited to the `:single` cache key.
  - Rollback: drop the `opts` argument in `routes.ts`.
- **A timed-out call keeps running** (review #7, accepted). After a 120 s `timeout` the provider request is not aborted, and a Retry can overlap it, billing twice across two generations. This is documented in `modules/brief/README.md` (step 7). The lock is not extended.
- **Scroll effect timing** (review #1). The effect waits for Smart Diff to settle and keys on the target's group, so a file moving out of `core` after load scrolls to its final card. If e2e still lands on the wrong card, the effect is running before the target card has mounted. Check that the settled-query gate reads the same `useSmartDiff` instance the groups come from.
  - jsdom has no `scrollIntoView`: stub it in tests.
- **Fact-pair drift** (review #3). Server and client each pin to `BRIEF_FACT_PAIRS` (steps 4 and 8). Adding a pair later means editing the contract (both copies), the emitter and `brief.json` together; either pin test fails otherwise.
- **Gate size warnings.** `pr-size` (> 40 files / > 1,500 lines) and `no-insights` will likely fire. They are WARNINGs: run `/engineering-insights` at the end of the chain.
- **Windows `.it` flakiness unrelated to this change** (`reviews.it`, `run-cost.it`, [server/INSIGHTS.md](server/INSIGHTS.md) 2026-09-29). Re-run the failing file alone and prove a baseline before reading it as a regression.
