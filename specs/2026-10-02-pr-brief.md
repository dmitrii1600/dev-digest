# Spec: PR Brief — one card that says what a PR does, where it is risky and what to read first
Spec ID: SPEC-2026-10-02-pr-brief
Status: approved
Supersedes: none
Packages: server, client, e2e

## Problem and user
A reviewer who opens someone else's PR "cold" has to put the picture together from three separate blocks: Intent and Blast radius on Overview, and the role-grouped diff on Files changed. Nothing tells them what the PR does in two sentences, what could break, or which `file:line` to read first. Today they read the description, scan the diff top to bottom and guess. The PR Brief puts those facts in one card on the Overview tab. It adds a model-written summary, Risk areas and a Review focus list, made by one model call over facts that are already computed. Diff hunk bodies are never sent to the model.
**Request vs tree:** The request mostly matches the tree. These points differ:
- `resolveFeatureModel` lives in `server/src/modules/_shared/feature-models.ts:56`, not in `modules/settings/`.
- The structured call re-asks the model up to 2 times on invalid output by default (`server/src/adapters/llm/openai.ts:90`, `:129`; `server/src/adapters/llm/anthropic.ts:92`, `:143`), which conflicts with "exactly one call". Resolved: zero schema re-asks (Q-1).
- The linked issue is not persisted. It is fetched live when the PR detail is read (`server/src/adapters/github/octokit.ts:91`, `:127-135`), and `pull_requests` has no column for it (`server/src/db/schema/pulls.ts:5-34`). Resolved: fetched live at generation time (Q-4).
- `PrBrief` requires `intent`, `blast`, `risks` and `history` together (`server/src/vendor/shared/contracts/brief.ts:161-167`). The only writer of `pr_brief.json` today writes just `history`, using a read-merge-write (`server/src/modules/blast/repository.ts:100-135`).
- No `/pulls/:id/brief` route exists, and nothing reads `client/messages/en/brief.json`.

## Goals / Non-goals
**Goals**
- A PR Brief section on Overview with a summary, Risk areas and Review focus, next to the existing Intent and Blast radius blocks.
- Every file the brief names is a changed file of the PR or a file in its blast map.
- The brief is generated only on an explicit request, with one model call, inside an 8,000-token input budget. It is stored per PR against the head SHA and shown again on reload without regeneration.
- Review focus items and risks jump to the exact file, and to the line when the diff shows it, on Files changed. The target survives Back and reload.
- The brief says explicitly which input facts were missing, degraded or trimmed.
**Non-goals**
- Automatic generation on page open, on a new head SHA, or after a review run (decision 2).
- Workflow-retro or cost-report attachments. They are process, not product.
- The Prior PRs accordion. It is L04 work and stays as it is.
- An MCP tool for the brief, and a brief inside the review prompt.
- Changing how Intent, Blast radius or Smart Diff are computed.
- Sending file contents from the clone, other than the attached Project Context documents.

## User stories
- **US-1** As a reviewer opening a PR cold, I want a short summary, the risk areas and a read-first list on the Overview tab so that I know what the PR does and where to start.
- **US-2** As a reviewer, I want to click a review-focus item or a risk and land on that file and line in Files changed so that I read the right code without searching.
- **US-3** As a reviewer, I want the brief to stay put across reloads, to tell me when the PR has moved on, and to regenerate only when I ask, so that I do not wait or pay twice.
- **US-4** As a reviewer, I want to trust the brief: it names no invented files, it says which facts it lacked, and text in the PR cannot steer it.
- **US-5** As a workspace owner, I want the brief to use the model chosen for "Risk Brief" in Settings, make one model call within a fixed budget, and be visible in the logs, so that cost is predictable.

## Acceptance criteria (EARS)
- **AC-1** WHILE no brief is stored for the PR, the Overview tab shall show the PR Brief section with "No brief yet", a one-line explanation and a Generate brief button. · traces: US-1 · verify: component
- **AC-2** WHEN the user activates Generate brief, the system shall build one brief, store it for the PR with the head SHA it was generated for, and show it. The inputs are the stored intent, the blast-radius summary and caller file list, the per-file additions and deletions with their Smart Diff role, the PR title and description, the linked issue, and the Project Context documents attached to the repo's enabled agents and their enabled skills. The linked issue is the one named by the first `#n` in the description, skipping `owner/repo#n` cross-repo references and `&#n;` HTML entities, and is fetched from GitHub at generation time. Documents are taken agent by agent, enabled agents ordered by creation time ascending and then by id ascending, each agent's own documents before its enabled skills' documents, and the first occurrence of a path wins. · traces: US-1, US-5 · verify: integration
- **AC-3** WHEN a brief is shown, the PR Brief section shall show the summary, a Risk areas list, and a "Review focus — read these first" list with its item count. The existing Intent block and Blast radius block shall be in the designed two-column layout, with Risk areas under Intent. · traces: US-1 · verify: component
- **AC-4** Each risk shall show its title, an icon for its kind (security, db_migration, breaking_api, perf, deps, or a generic icon for any other kind) coloured by severity, its severity as a visible word (AC-16), and its first file reference. WHEN the user activates the risk's expander, the section shall show its explanation and every file reference, and close any other open risk. · traces: US-1 · verify: component
- **AC-5** Each review-focus item shall show `<file>:<line> — <reason>`, in the order the model gave. · traces: US-1 · verify: component
- **AC-6** The system shall keep a file reference in a risk or review-focus item only when its path is a changed file of the PR or a file in the blast map used for that generation. Before comparing, the system shall remove a trailing `:<line>` or `:<start>-<end>` suffix and a leading `./`. A risk left with no file reference shall be removed. A review-focus item whose file fails the check, or whose line is not an integer ≥ 1, shall be removed. · traces: US-4 · verify: unit
- **AC-7** The stored brief shall list every input fact that was absent, degraded or trimmed, with the reason, and the section shall show that list under the summary. The facts are: intent absent, or "derived for an older commit" when its head SHA differs from the PR's; blast map unavailable or degraded, with its reason; no linked issue, or the issue was not retrieved (missing GitHub token or failed fetch); no Project Context documents, or documents skipped, truncated or dropped for the budget; description empty or truncated; linked-issue body cut, caller list dropped, or file statistics folded for the budget (EC-9). · traces: US-4 · verify: integration
- **AC-8** WHEN the user activates a review-focus item whose file is in the PR's diff, the page shall switch to Files changed (`?tab=diff`) and expand the file's role group and file card. It shall mark that card with an accent border and scroll it into view, then scroll to the item's line when the diff shows that new-side line. The target file and line shall be carried in the URL as in AC-17. · traces: US-2, DR-22 · verify: e2e (a browser flow against a seeded brief for PR #482)
- **AC-9** WHEN the user activates a risk's main part or a file reference in its explanation, the page shall navigate as in AC-8 to that file, and to the line that the reference carries. · traces: US-2 · verify: component
- **AC-10** WHEN the user opens or reloads the PR page and a brief is stored, the section shall show the stored brief and make no model call. · traces: US-3 · verify: integration
- **AC-11** WHEN the user activates the refresh button ("Re-run the brief for this PR"), the system shall generate a new brief as in AC-2, replace the stored brief, and show the new one. · traces: US-3 · verify: integration
- **AC-12** WHILE a generation is running for the PR, the section shall show a two-card skeleton in place of the brief-owned body (the missing-facts list, Risk areas and Review focus) and a progress indicator in place of the score, keep the Intent and Blast radius blocks visible, and disable Generate and refresh. · traces: US-3 · verify: component
- **AC-13** WHEN a brief is shown, the banner above it shall show the verdict, the findings and blockers count, and the PR score of the PR's newest review record of kind `review` across all agents, with the brief's summary as its text. Blockers are that review's undismissed CRITICAL findings. It shall also show the brief's cost and its input and output tokens, and an info tooltip stating that the verdict, findings and score come from the latest review while the summary, risks and review focus come from the brief. · traces: US-1 · verify: component
- **AC-14** WHILE the stored brief's head SHA differs from the PR's current head SHA, the section shall show the stored brief with a Stale marker that names both short SHAs (generated for X, PR now at Y), next to the refresh button. It shall start no generation. · traces: US-3, DR-19 · verify: component
- **AC-15** WHEN a brief is generated, the system shall call the provider and model chosen for "Risk Brief" in the workspace's feature-model settings, and record that provider and model with the brief. · traces: US-5 · verify: integration
- **AC-16** Each risk shall show its severity as a visible word ("high", "medium" or "low") next to the severity colour. · traces: US-1, DR-21 · verify: component
- **AC-17** WHEN the page opens with `?tab=diff` and a target file and line in the URL (including on reload or after Back), Files changed shall expand, mark and scroll to that file and line as in AC-8. · traces: US-2, DR-22 · verify: component

## Edge cases
- **EC-1** IF no intent is stored for the PR, THEN the system shall generate the brief without it, start no intent derivation, and list intent as missing. · traces: DR-9 · verify: integration
- **EC-2** IF the blast map is unavailable or degraded (`flag_off`, `index_failed`, `index_partial`, `index_stale`, `repo_too_large`, `no_data`), THEN the system shall generate the brief and list the blast radius as degraded with that reason. With no blast map, the file check in AC-6 shall use the PR's changed files alone. · traces: DR-9 · verify: integration
- **EC-3** IF the model call fails (including a transport failure, which is not retried), does not finish within 120 seconds, or returns output that does not match the brief shape (no re-ask is made), THEN the system shall answer 502 `brief_failed` with the reason `llm_error`, `timeout` or `invalid_output`, store nothing and keep any previous brief. The section shall show an error naming the failure, with a Retry action. · traces: DR-10 · verify: integration
- **EC-4** IF no API key is configured for the provider chosen for "Risk Brief", THEN the system shall answer 422 `provider_key_missing` naming the provider and make no model call, and the section shall name the provider and link to Settings. · traces: DR-10 · verify: integration
- **EC-5** IF a generate request arrives while a generation for the same PR is running, THEN the system shall reject it with 409 `brief_running` and start no second model call. · traces: DR-11 · verify: integration
- **EC-6** IF the target file of a review-focus item or a risk is not in the PR's diff (it is only in the blast map), THEN the page shall stay on Overview and show an info notice, "File not in this PR's diff", that disappears after 4 seconds. · traces: US-2 · verify: component
- **EC-7** IF the diff does not show the target line (the line lies outside the shown hunks, the file has no displayable patch, or the line in the URL has no anchor), THEN the page shall scroll to the top of the file card and show no error. · traces: DR-12 · verify: component
- **EC-8** IF no risk survives the file check, THEN Risk areas shall show "No notable risks flagged." IF no review-focus item survives, THEN the Review focus card shall be hidden. · traces: DR-13 · verify: component
- **EC-9** IF the assembled model input exceeds 8,000 tokens, THEN the system shall drop Project Context documents from the end of the attach order, then truncate the PR description, then cut the linked-issue body, then drop the caller file list beyond the blast summary, then fold the statistics of the lowest-churn files into one "N more files, +A −D" line, stopping as soon as the input fits. It shall keep the intent and the blast summary, and record each step under AC-7. IF the input still exceeds 8,000 tokens after all five steps, THEN the system shall refuse generation with 422 `brief_input_too_large` and make no model call. · traces: DR-14 · verify: unit
- **EC-10** IF the PR has no changed files recorded, THEN the system shall refuse generation with 422 `no_changed_files`, make no model call, and the section shall ask the user to reload the PR. · traces: DR-15 · verify: integration
- **EC-11** IF the PR's stored document holds a cached Prior PRs result, THEN generating a brief shall leave that result unchanged, and refreshing Prior PRs shall leave a stored brief unchanged. A document holding only the Prior PRs result shall count as "no brief yet". · traces: DR-16 · verify: integration
- **EC-12** IF the PR has no review yet, THEN the banner shall show the brief's summary without a verdict, a findings count or a score, and with no placeholder score. · traces: DR-18 · verify: component
- **EC-13** IF the target file in the URL is not a file of the PR's diff, THEN Files changed shall open at the top with no card marked and no error. · traces: DR-12 · verify: component

## Design review
**Source:** `specs/designs/pr-brief/01-overview-brief.webp`, `02-files-changed-smart-order.png`, `03-verdict-banner-highlight.webp`, `04-risks-and-review-focus-highlight.webp`, `05-files-changed-after-focus-click.webp` and `06-pr-brief-behaviour.md`. The design shows the empty, loading and ready states and the not-in-diff toast. All other states were checked against the tree.
### Gaps
- **DR-1** Generating, storing and serving a brief: no `brief` module and no `/pulls/:id/brief` route exist (`server/src/modules/index.ts:1-16`).
- **DR-2** Contract: `PrBrief` has no `summary`, no `review_focus`, no generation record (head SHA, provider, model, tokens, cost, generated at) and no missing-facts list. It requires all four parts at once (`server/src/vendor/shared/contracts/brief.ts:161-167`), while `pr_brief.json` is written piece by piece (`server/src/modules/blast/repository.ts:115-135`). A document holding only `history` cannot satisfy it. `summary` and `review_focus` go into both copies of `brief.ts`.
- **DR-3** The Project Context reader resolves documents for one agent (`server/src/modules/project-context/service.ts:393-400`). Nothing builds the union over all enabled agents (`server/src/db/schema/agents.ts:43`) and their enabled skills.
- **DR-4** The linked issue's text is not stored anywhere. It is read live at PR fetch (`server/src/adapters/github/octokit.ts:127-135`), and intent resolves `#n` references live and keeps no text (`server/src/modules/intent/service.ts:261-265`).
- **DR-5** Files changed has no navigation target. It has no file or line anchors, and nothing outside it can expand its groups or cards (`client/src/app/repos/[repoId]/pulls/[number]/_components/DiffTab/DiffTab.tsx:34-46`, `.../page.tsx:206-213`).
- **DR-6** Blast radius and Smart Diff role grouping exist only inside their own module plugins (`server/src/modules/blast/routes.ts:29-52`, `server/src/modules/smart-diff/README.md:1-4`). Neither is a `Container` port, and the cross-module rule forbids reaching in (`server/INSIGHTS.md:203`).
- **DR-7** The verdict banner shows a review's own summary only. It has no info tooltip, no refresh, no cost line and no loading state (`client/src/app/repos/[repoId]/pulls/[number]/_components/VerdictBanner/VerdictBanner.tsx:12-60`).
- **DR-8** Copy: `unavailableHint` ("Run a review or open the PR to compute it.") contradicts decision 2. `block.risks` reads "Risks" where the design says "Risk areas". There are no keys for the empty state, Review focus, Stale, the missing-facts list, the notice or the tooltip (`client/messages/en/brief.json`).

- **DR-9** No intent, a degraded blast map, no linked issue → EC-1, EC-2, AC-7
- **DR-10** Generation fails, times out, or no provider key → EC-3, EC-4
- **DR-11** Double submit or a second tab → EC-5
- **DR-12** The target line is not shown in the diff, or a URL target names a file not in the diff (an edited link, or a new head SHA) → EC-7, EC-13
- **DR-13** Zero risks or zero focus items after the file check → EC-8
- **DR-14** Input over budget → EC-9
- **DR-15** PR detail never fetched, so no changed files are recorded (`server/INSIGHTS.md:255`) → EC-10
- **DR-16** `pr_brief.json` is shared with the Prior PRs cache → EC-11
- **DR-17** Narrow viewport, long paths and keyboard-only use → NFR-7, NFR-12
- **DR-18** No review exists, so there is no verdict or score → EC-12
- **DR-19** Stale brief (new head SHA) → AC-14

## Non-functional requirements
- **NFR-1** Cost: a generation makes exactly one model call, with no schema re-ask and no transport-level retry. Opening the page, reloading, switching tabs, expanding risks and jumping make none. A generation never derives intent, never runs a review and never starts any other model call. · verify: integration
- **NFR-2** Size: the model input is at most 8,000 tokens, counted as cl100k_base tokens by the project tokenizer that Project Context uses (`server/src/adapters/tokenizer/index.ts:1-14`), across all messages sent. · verify: unit
- **NFR-3** Security: no diff hunk body (patch text) and no clone file contents other than the attached Project Context documents reach the model. Every PR-sourced, issue-sourced, document-sourced and index-sourced text is wrapped as untrusted, documents are labelled with their path, and `INJECTION_GUARD` is unchanged. · verify: unit
- **NFR-4** Output bounds: a stored brief has a summary of at most 600 characters, at most 8 risks and at most 8 review-focus items. A title is at most 120 characters, an explanation at most 600 and a reason at most 200. Longer text is cut with an ellipsis, and extra items are dropped in order. · verify: unit
- **NFR-5** Degraded mode: a stored brief stays viewable when the provider key is removed, repo-intel is off, the index is gone or the intent is deleted. · verify: integration
- **NFR-6** i18n: every new user-facing string comes from `client/messages/en/brief.json` (or the existing `prReview` namespace for banner labels), and none is hard-coded. · verify: static
- **NFR-7** Accessibility: each risk's main part, its expander and each review-focus item is a keyboard-reachable button. The expander exposes its expanded state. A focus item's accessible name includes `<file>:<line>`. Severity and Stale are conveyed by visible text as well as by colour. · verify: component
- **NFR-8** Concurrency: at most one generation runs per PR. A generation keeps running when the user leaves the page, and the next visit shows its result. A generation still running after 10 minutes counts as failed, so it cannot lock the PR. · verify: integration
- **NFR-9** Observability: each generation logs one line with the PR id, head SHA, provider and model, the number of model calls, input tokens counted before the call, provider input and output tokens, cost (unknown stays null, never 0), duration, what was trimmed, and how many risks and focus items the file check removed. · verify: integration
- **NFR-10** Compatibility: both copies of `brief.ts` are byte-identical after the change. The Intent block, the Blast radius block, Prior PRs and the Description keep their current behaviour on Overview. · verify: static
- **NFR-11** Data retention: each PR keeps one stored brief. Refresh replaces it, and deleting the PR deletes it (`server/src/db/schema/reviews.ts:99-103`). · verify: integration
- **NFR-12** Layout: below 768 px viewport width the two columns stack into one. Long paths and reasons wrap without horizontal scrolling, and the refresh button stays visible. · verify: component, plus manual (resize the browser below 768 px and check the stacking)
- **NFR-13** Rate: Generate requests are limited to 10 per minute; checked as a pinned constant, because the rate limiter is off under `NODE_ENV=test`. · verify: static

## Untrusted inputs
| Input | Source | Validation | On invalid |
|---|---|---|---|
| PR title and description | GitHub, via `pull_requests` | Text that reaches a prompt: wrapped as untrusted; description truncated to fit the budget | An instruction inside is data and is never followed; the cut is listed (AC-7) |
| Linked issue title and body | GitHub issue read | Text that reaches a prompt: wrapped as untrusted; bounded by the budget | Not retrieved → generation continues and the issue is listed as missing |
| Project Context documents | `server/clones/<repo>/**` through the existing reader | Paths stay under the clone; wrapped and path-labelled; ≤ 64 KB each; dropped to fit the budget | Unreadable → skipped and listed; over budget → dropped and listed |
| Changed-file paths, symbol names, caller paths | GitHub diff metadata; repo-intel index of the clone | Wrapped as untrusted in the prompt; rendered as plain text | A path never reaches the filesystem; odd characters render as text |
| Stored intent text | Earlier model output | Wrapped as untrusted in the prompt | Treated as data |
| Summary, risk title, explanation, reason | LLM output | Shape and bounds: the brief contract; lengths per NFR-4; rendered as plain text | Contract mismatch → EC-3; over-long → cut with an ellipsis; HTML shown as text |
| Risk severity and kind | LLM output | Severity is `high`, `medium` or `low`; kind is free text | Severity mismatch → EC-3; unknown kind → generic icon (AC-4) |
| File references and review-focus paths | LLM output | The path check in AC-6 | Reference or item removed and counted (NFR-9) |
| Review-focus line | LLM output | Integer ≥ 1 | Item removed (AC-6); a line not shown in the diff → EC-7 |
| PR `:id` | HTTP params | Identity: a uuid that resolves to a PR in the caller's workspace | 422 for a malformed id; 404 otherwise, the same as "does not exist" |
| `POST` body | HTTP | None accepted; the route takes no body | Ignored; it never influences generation |
